# --- OCR des sources NON japonaises (anglais, français, coréen, chinois...) ---
# `manga-ocr` est un modèle japonais : son décodeur n'a pas de token d'espace (le japonais
# n'en écrit pas). Sur une planche anglaise il ne rend pas un texte approximatif, il rend
# une chaîne collée et parsemée de kanji INVENTÉS — mesuré sur un webtoon anglais :
#   « HE'S CERTAINLY NO ORDINARY PERSON » → « ＨＥＳＣＥＲＴＡＮＡＹＮＯＯＯＲＤＩＮＡＲＹＰＥＲＳＯＮ »
#   une date                             → « ２０１６年１０月１９日に２０日 »
# Le LLM traduit ensuite cette bouillie sans broncher : le défaut est invisible au rapport.
# RapidOCR (PP-OCRv4 en ONNX) lit le latin AVEC les espaces, embarque ses modèles dans la
# roue, tourne hors ligne sur CPU et n'exige pas torch. Mesuré sur la planche qui a motivé
# ce changement : les 10 bulles relues correctement, dont celle citée ci-dessus.
#   Tire `opencv-python` (~44 Mo), `shapely` et `pyclipper` — la roue elle-même fait ~15 Mo.
#   ⚠ Il DÉPEND de `onnxruntime`. Si tu as installé `onnxruntime-directml` (mutuellement
#   exclusif, cf. plus bas), un `pip install` non qualifié te réinstallerait `onnxruntime`
#   par-dessus. Dans ce cas :  pip install --no-deps rapidocr-onnxruntime
#   Inutile si tu ne traites que du japonais : le pipeline ne l'importe qu'au besoin, et
#   dit quoi installer le jour où il en a besoin.
#   ⚠ LIMITE connue : son détecteur rate parfois une bulle de PONCTUATION SEULE (`...`), là
#   où manga-ocr la lisait. La bulle ressort vide ; c'est le prix à payer, et il est sans
#   commune mesure avec ce qu'on gagne sur le texte.

# --- Vitesse de l'OCR — OPTIONNEL ---
# Sans `torchvision`, `transformers` se rabat sur un processeur d'image en PIL, plus lent :
#   « ViTImageProcessor requires torchvision (not installed); falling back to
#     ViTImageProcessorPil for backward compatibility »
# L'avertissement lui-même est déjà tu par `manga/ocr.py` ; il ne reste que le surcoût.
# Volontairement PAS une dépendance dure : `torch` peut être installé en build `+cpu` ou
# CUDA, et un `pip install torchvision` non qualifié réinstallerait un `torch` incompatible.
# Prends la roue qui correspond à TON torch (`python -c "import torch; print(torch.__version__)"`) :
#   pip install torchvision --index-url https://download.pytorch.org/whl/cpu    # torch +cpu
#   pip install torchvision                                                      # torch CUDA

# --- Accélération GPU (AMD/Windows) — OPTIONNEL, repli CPU automatique sinon ---
# La détection de bulles (ONNX) peut tourner sur GPU via DirectML (DX12, marche sur
# toute carte AMD/NVIDIA/Intel récente sous Windows — pas besoin de ROCm/CUDA) :
#   pip uninstall onnxruntime && pip install onnxruntime-directml
# ⚠ onnxruntime et onnxruntime-directml sont MUTUELLEMENT EXCLUSIFS : n'installe
# que l'un des deux. Le CPU reste largement suffisant en pratique (~1-3 s/planche
# pour la détection, ~0,5-2 s/bulle pour l'OCR) — n'active DirectML que si tu
# traites de gros volumes et veux accélérer.
# Active ensuite "DmlExecutionProvider" dans config.yaml > manga.detection.providers.
